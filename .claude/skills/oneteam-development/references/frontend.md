# 프론트엔드

`frontend/CLAUDE.md` 에 있는 상시 규칙 위에, 실제로 화면을 만들 때 판단이 필요한
것들만 적는다.

실제 `package.json`, lockfile, ESLint 와 Prettier 설정이 이 문서보다 우선한다.
팀 합의 없이 프레임워크나 상태 관리 라이브러리를 바꾸지 않는다.

## 지금 들어와 있는 것

Vite, React, TypeScript, Tailwind 뿐이다. 라우터도 서버 상태 라이브러리도 없다.
화면이 여러 개 필요해지면 그때 팀에 알리고 넣는다. 그 전까지는
`useState` 와 `useEffect` 로 충분하다.

## 무엇을 어디에 두나

- `lib/`: API 클라이언트, 포맷 함수처럼 화면과 무관한 유틸
- `components/`: 여러 화면에서 쓰는 UI 조각
- `features/{도메인}/`: 그 도메인에서만 쓰는 화면 조각

**한 컴포넌트에 조회, 상태 전이, 화면 표현을 전부 넣지 않는다.** 파일이 길어지면
데이터를 가져오는 부분을 훅으로 빼고, 표현만 남긴다. 다만 아직 한 곳에서만 쓰는
것을 미리 공용으로 빼지는 않는다. 두 번째 사용처가 생겼을 때 뺀다.

## 비동기 화면

네 가지 상태를 모두 처리한다.

| 상태 | 화면 |
|---|---|
| 로딩 | 스피너나 스켈레톤. 빈 화면으로 두지 않는다 |
| 성공 | 데이터 |
| 비어 있음 | "아직 없습니다" 같은 안내. 성공인데 목록이 0개인 경우다 |
| 에러 | 무엇이 잘못됐는지와 다시 시도할 방법 |

- **서버가 성공을 돌려주기 전에 화면에서 먼저 확정하지 않는다.**
- 제출 버튼은 요청 중에 비활성화한다. 두 번 눌려서 두 번 등록되는 것을 막는다.
- 에러를 `console.log` 로만 남기고 화면에는 아무것도 안 보여주지 않는다.

## 정리

`useEffect` 안에서 시작한 것은 반환하는 정리 함수에서 끝낸다.

```tsx
useEffect(() => {
  const controller = new AbortController()
  api('/api/orders', { signal: controller.signal }).then(setOrders)
  return () => controller.abort()
}, [])
```

타이머(`setInterval`), 이벤트 리스너(`addEventListener`)도 같다.
React StrictMode 가 개발 모드에서 effect 를 두 번 실행하므로, 정리를 빼먹으면
개발 중에 요청이 두 번 나가는 것부터 눈에 띈다.

## API 와 보안

- 모든 요청은 `@/lib/api` 의 `api()` 를 거친다. 컴포넌트에서 `fetch` 를 직접 부르지 않는다.
- 경로는 상대경로로 쓴다. `http://localhost:8080` 을 코드에 넣지 않는다.
- 토큰과 환경값을 소스에 하드코딩하지 않는다. `import.meta.env.VITE_*` 로 읽는다.
- **화면에서 버튼을 숨기는 것은 권한 처리가 아니다.** 서버가 실제로 막아야 한다.
- 로그인이 만료된 것과 권한이 없는 것을 구분해서 안내한다.

## 타입

- `any` 를 쓰지 않는다. 모르겠으면 `unknown` 으로 받고 좁혀서 쓴다.
- API 응답 타입은 한 곳에 모아두고 화면에서 가져다 쓴다. 같은 응답의 타입을
  화면마다 따로 적지 않는다.

## 접근성

여기까지만 지킨다. 더 들어가지 않는다.

- 버튼은 `<button>`, 링크는 `<a>` 로 쓴다. `<div onClick>` 을 쓰지 않는다.
- 입력에는 `label` 을 연결한다.
- 이미지에 `alt` 를 넣는다.
- 오류 메시지는 그 입력 바로 옆에 보여준다.
