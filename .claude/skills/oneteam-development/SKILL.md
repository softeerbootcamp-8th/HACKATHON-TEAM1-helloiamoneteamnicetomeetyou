# 원팀 개발 지침

**개발 기간이 짧다. 범위를 좁게 잡고 동작하는 것부터 순서대로 만든다.**
지금 필요 없는 추상화, 근거 없는 인프라 추가, 짐작으로 하는 성능 최적화는 하지 않는다.
선택지의 차이가 작으면 하나로 정하고 저장소 전체가 같은 방식을 쓴다.

작업 범위에 해당하는 문서만 읽는다.

- API 응답 형식, 에러 코드, URL 규칙을 다루면 [contracts.md](references/contracts.md)
- Spring 코드를 구현하거나 리뷰하면 [backend.md](references/backend.md)
- 프론트엔드 코드를 구현하거나 리뷰하면 [frontend.md](references/frontend.md)
- Git, 환경 변수, PR, 위험한 명령을 다루면 [workflow.md](references/workflow.md)

## 작업 순서

1. 루트 `CLAUDE.md` 와 작업 영역의 `CLAUDE.md` 를 확인한다.
2. 고칠 코드와 그 주변을 먼저 읽는다.
3. 프론트와 백이 함께 쓰는 약속(API Method, Path, 응답 형식)이 바뀌는지 먼저 본다.
   바뀌면 반대편 영역도 같이 고쳐야 하므로 시작 전에 알린다.
4. 요청받은 범위만 구현한다.
5. 바뀐 영역의 테스트, lint, 빌드를 돌린다.
6. 바꾼 것과 검증 결과, 확인하지 못한 것을 보고한다.

## 애매하면 물어보는 것

혼자 정하지 않고 팀에 확인한다. 대신 확인을 기다리는 동안 멈추지 말고,
가정을 적어두고 나머지를 진행한다.

- 인증 방식과 토큰 저장 위치
- API 의 Method, Path, 응답 필드 이름
- DB 스키마
- 새로 추가하는 의존성
- 배포와 환경 변수
